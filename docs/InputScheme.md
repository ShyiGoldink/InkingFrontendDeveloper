# 输入方案（设计稿）

> 状态：设计稿，**未实现**。这里记录讨论后定下的方向，将来实现时对照本文。
> 只讲输入与命中，不含渲染层 / SDF / 样式。

## 1. 一句话

**表管「可见壳 + 静态/动画控件」，内容管「算术映射 + 自管理 + 捕获」。**

静态和「整块在动」的 UI 由坐标索引表负责命中；规则内容（无限表格、长列表、画布）不进表，
自己用算术定位；一切拖动类交互靠指针捕获，而不是靠命中。

## 2. 三档 UI 与各自的命中方式

| 档位 | 判据 | 命中方式 | 代价 |
| --- | --- | --- | --- |
| 静态（页面、面板、菜单栏、按钮组） | 两次配置变更之间几何不变 | 烘焙成索引表，脏了才重烘 | 查表 O(1)，每帧 0 |
| 整块在动（抽屉、Toast、下拉、弹窗） | 动的是一棵子树，子树内部相对位置不变 | 子树自带子表 + 变换通道 | 全程 0 次重烘，查表时把点反变换 |
| 每帧自变形（粒子、进度指示器、动态碰撞体） | 形状每帧都在变 | 不进表，自己响应 | 只有它自己付代价 |

纯装饰动效（光效、呼吸）应能标记「不可命中」，连判断都省。

## 3. 表的结构

### 3.1 key 必须离散

`unordered_map<矩形, 控件>` 做不到：矩形当 key 只能精确匹配，答不了「包含」。
能当 key 的只有离散位置——格子索引，或者规则网格的行列号。

### 3.2 基本形态

网格索引 + CSR 候选数组（`src/ink/ui/HitTable.cpp` 现在已是这个形态）：

- 包围盒按格子边长切方格，每条条目登记进它覆盖到的所有格子；
- 查表 = 一次除法定位格子 + 扫该格候选；
- 候选按 zindex 降序填，「第一个真正包含该点」的就是最上面那个；
- 格子只负责缩小范围，是否命中仍由矩形自己判定，所以不会邻格误命中；
- 零分配、零指针追逐、零哈希（换成哈希 key 语义等价，数组更省更连续）。

### 3.3 不要均匀切格，按 UI 分布聚类

均匀网格有两条代价：建表要遍历整个画布（与 UI 有多少个无关）；粒度被迫折中
（粗了密集区候选多、早退失效，细了空白区格子数按面积涨）。

聚类方案：

- 粗块（只有含 UI 的块才存在）+ 块内细分，每个簇用自己的 cellSize；
- 查询 = 定位簇（簇数量少，线性或二分）→ 簇内查表；
- 额外收益：只碰一两个簇，热数据集中，缓存友好；
- 建表时间正比于 UI 数量，不再正比于画布面积。

### 3.4 形状决定索引

生成器按配置里的布局类型挑专用结构，而不是让人去调一个通用 cellSize：

| 布局 | 结构 | 复杂度 |
| --- | --- | --- |
| 等宽等距（菜单栏、工具栏、分页条） | 纯算术 `index = (x - rowX) / (w + gap)` | O(1)，无表 |
| 不等宽但数量固定 | 排序区间数组 + 二分（k 小就直接线性） | O(log k) |
| 规则网格（tile、矩阵、表格） | 行列取整 | O(1)，无表 |
| 散乱 | 簇内小表 | 见 3.3 |

通用结构只是兜底。编译期知道一切的最大收益不是「空间索引调参更准」，
而是对每种布局生成专用查找。

### 3.5 三条必须写死的规则

1. **兜底条目单独存**：空白区不进表，点在空白的答案来自一条「全局兜底条目」
   （根场景 / 背景板），簇查完没命中再问它，不要复制进每个簇。
2. **溢出桶**：运行时新增的 UI 不在生成的结构里，必须有线性列表兜住，
   命中时与簇结果比 zindex。没有这条，动态 add 的场景就是 bug。
3. **跨簇条目**（下拉菜单压在菜单栏和面板上）：登记多份还是抬到粗层，
   规则必须先定，否则遮挡与层级会错。

## 4. 层级与事件语义

- zindex 显式化：现在层级是「构造顺序隐含的全局序号」（`src/ink/ui/Scene.cpp` 的 `nextOrder`），
  将来要支持显式设置与调整。
- 从 zindex 高的往下扫，**命中并阻塞就停**——这就是「快照 + 阻塞」。
- 三种结果必须分开：命中且阻塞 / 命中但不阻塞（穿透）/ 未命中。
- **冒泡到父场景**（现在的做法）与**穿透到下一层**是两种语义，要分别定义；
  半透明遮罩挡点击靠的是前者。
- **遮挡 ≠ 未命中**：动画中的抽屉、遮罩要能回答「这里被挡住了」，而不是「这里没东西」。
- 隐藏的子树不进表、不参与命中。

## 5. 动画：配置 + 编译期采样

- 动画写在配置（CXXCSS）里，生成器把曲线烘成「每帧一个值」的采样表；
  播放就是一次数组索引——没有贝塞尔求值、没有 easing 分支、内存连续。
- **变换通道优先**：平移 / 缩放 / 旋转不改表，查表时把点反变换进容器本地空间
  （平移缩放的逆是解析的；旋转后父层那条 AABB 也按帧采样好）。
  表全程冻结，每帧只写一个「当前采样索引」。
- 配置语法上把 **transform 通道**（translate / scale / rotate / opacity）与
  **layout 通道**（width / height / 会导致兄弟重排的定位）分开：
  前者不碰表，后者必须重烘受影响的子树，且受影响范围由生成器算好。
- 两端稳定态（抽屉关 / 开）= 两张烘好的表 + 中间变换插值，全程 0 次重烘。
- **命中与渲染必须用同一个 t 的快照**，否则快速动画下会差一帧（画在这儿、点在那儿）。
- **动画期间 hover 必须每帧重算**：鼠标不动、抽屉滑过来，指针底下的控件已经变了，
  但没有任何鼠标事件会触发。
- 长驻循环动效（呼吸、跑马灯）用短表循环或保留解析式，别烘长时间轴。
- 采样表体积 = 时长 × 采样率 × 通道数（1 秒 120Hz 单通道 120 个 float，可忽略）。

## 6. 输入路由

- 快照：命中一次 → 缓存结果 → 用它回答 hover / 按下 / 抬起 / 点击。
- 按下时记住目标，抬起时还算不算同一个：不算就发 Cancel（现在 `InputRouter` 已是这个语义）。
- **pointer capture 是一等公民**：按下即捕获，之后的 move / up 直投捕获者、不再查表，
  抬起释放。滚动条、分割条、拖窗口、框选全靠它，不要为每个用例打补丁。
- 事件不分配：回调直投命中目标，不做广播。

## 7. 无限 / 虚拟化内容（Excel 型）

前提是「无限」永远不进表：

- 表里只装 viewport + 缓冲的可见格（例如 40×25 = 1000 格）；
  总行数是数据层的概念，内存上限 = 可见格数 × 每格条目，与总行数无关。
- 滚动 = 变换：点反变换到内容坐标，取整得 (col, row)，O(1) 查或算。
- 规则网格不需要空间索引（坐标 → 索引是算术），所以「内容自管理」不仅可行，
  而且比通用表更快。
- 拖选单元格这类**范围查询**只有规则网格能做，哈希表做不到。
- 单元格实例池化复用，只有可见的几十个存在。
- 空白格点击由网格自己兜（= 选中那个单元格），不需要表兜底。

## 8. 复杂度小结

- 常见：命中最高层即停，1~2 层，每层 O(1) → 整体 O(1)。
- 最坏：点在空白或一路穿透到底 → O(总条目数)，不是层数的平方。
- 建表：聚类后正比于 UI 数量，不再正比于画布面积。

## 9. 脏标记边界

现在 `Scene::invalidate()` 是从自己一路标脏到根。有了多层表之后这会把祖先全部弄脏、白重烘，
要改成**标到最近的表边界为止**：谁自带表，谁就是脏标记的终点。

## 10. 与现状的差距（待办）

现状：`include/ink/ui` + `src/ink/ui` 已有 Scene / Button / HitTable / InputRouter / SceneRegistry，
静态烘焙 + 动态洞可用；均匀 64px 网格；层级 = 构造顺序；无捕获、无遮挡结果、无变换通道、
无聚类、无溢出桶。

按优先级：

1. 表边界（谁自带表）+ 脏标记只标到边界；
2. pointer capture；
3. 遮挡结果与命中结果分离（三态返回）；
4. zindex 显式化；
5. 变换通道（offset / scale 不入表，查表时反变换点）；
6. 聚类索引 + 按布局类型生成专用查找；
7. 溢出桶。

## 11. 开放问题

- 跨簇条目的登记规则；
- 溢出桶与簇结果之间怎么统一比 zindex；
- 旋转容器 AABB 的采样密度（按帧？按角度？）；
- capture 期间的可视反馈（hover 状态怎么维持）；
- 命中结果是否要返回「路径」而不只是最上面那个（自定义分发要用）；
- 多窗口 / 多指针（触摸）下的 capture 归属；
- 配置语法：transform 通道与 layout 通道怎么表达；
- letterbox / DPI 换算与设计坐标归一（现在 `toDesign()` 做的是这件事）。

# 输入与命中方案（设计稿）

> 状态：设计稿，**未实现**。
> 2026-09-25 修订：输入从「命中一次 → 快照缓存」改成 **isDirty + 三态 query**；
> 写入口改 `final`，`[√]` 语义收窄成「可重写钩子」，场景层不再有布局变化。
> 本文只讲输入与命中，不含渲染层 / SDF / 样式。
>
> 文中出现的 `src/ink/ui/HitTable.cpp`、`Scene.cpp`、`InputRouter`、`SceneRegistry`
> 都指 `test001` 分支上的原型（`b135111 feat:按钮原型测试`）。本仓库 `dev001`
> 的 ui 层还没落地，原型只当参考实现看。

## 1. 总原则

**静态查表，动态自判，按 zindex 合并三态。所有命中相关变化收敛到 `isDirty`，每帧只判断一次。**

- 静态（场景 + 静态组件）几何不变，直接查烘焙好的表；
- 动态组件自己判断、自己维护状态，不进表，也不被遍历；
- 谁盖着谁由显式 zindex 决定，不看遍历顺序。

## 2. 场景约束

- **场景自身不做布局变化**：没有 `move` / `setPosition`，场景只负责「渲染 / 不渲染」。
- **但锚点还在**：场景第一次渲染总要有对齐的锚点，决定它摆在窗口的哪里。自身锚点决定自己
  以内部哪个位置去对应，上级锚点决定这个位置对上窗口的哪里。锚点是编译期定型的，初始化算一次，
  之后没有运行期位置写入口——它和「不做布局变化」不冲突，反而是场景能一直静态的前提。
- **同期只有一个场景可渲染**：其它场景数据还在，但不渲染，需要手动关闭。
- **动态需求压在 widget 层**：场景层永远静态，递归检查只需查 widget 树。
- **构造方式决定初始契约**：
  - `InkingScene(string)`：配置驱动，接受生成器分析，保留优化。
    这里的「优化」不是输入输出优化，而是**让代码生成器直接生成新类**，
    编译期就把行为和属性改掉。蚊子肉也是肉。
  - `InkingScene(SceneData)`：运行时构造，最大自定义，降至普通。

## 3. 写入口与钩子

- **写入口 `final`，不可重写**：`setPosition` / `setSize` / `setVisible` / 层级等。
- **写入口内部统一 `markDirty()`**：标脏由框架保证，不会漏。
- **只允许重写钩子**：`onPositionChanged` / `onSizeChanged` / `onVisibleChanged`。
- **`[√]` 语义收窄**：从「可重写 setter」改为「可重写钩子」。
- 钩子只做附加逻辑，**不负责标脏，也不拦截写入口**。

> 场景没有 position / size 写入口（第 2 节），所以 position / size 这一档写入口属于
> 组件层；场景层只有可见性这一档。

## 4. 标脏规则

**会标脏的变化（影响命中）：**

| 变化 | 说明 |
| --- | --- |
| 几何 | position / size |
| 可见性 | hide / show |
| 层级 | zindex |
| 鼠标移动 | 指针位置变了，命中结果就可能变 |

**不会标脏的变化（不影响命中）：**

- 颜色 / 文字 / 透明度；
- 不影响命中的装饰动效（呼吸、光效）。纯装饰动效还应能标记「不可命中」，连判断都省。

**重绘 ≠ 标脏：**

- 重绘的原因影响命中 → 标脏；
- 重绘的原因不影响命中 → 不标脏；
- 判断在 setter 里完成，不在重绘时判断。

## 5. isDirty 生命周期

```cpp
鼠标移动 / 几何变化 / 层级变化 / 可见性变化
    → makeDirty()
    → isDirty = true

每帧：
    if (isDirty) {
        query(鼠标位置, false)   // hover
        帧计数++
        连续 N 帧无 makeDirty → isDirty = false
    }

点击：
    query(鼠标位置, true)        // 不经过 isDirty，单独调一次
```

- 帧计数取 2~3 即可，鼠标停下后多算几帧无所谓。
- 动画动的那一帧会 makeDirty，不动的那几帧不 query，hover 状态不变，正确。

## 6. query 与三态返回

```cpp
HitResult query(Point point, bool isClick) {
    按 zindex 从高到低：
        静态层 → 查表
        动态层 → 自己判断（或自维护状态）
        阻塞   → 返回 Block
        穿透   → 继续
    返回 Miss（兜底）
}
```

- 点击和 hover 共用同一个函数。点击时 `isClick = true`，hover 时 `false`。
- 三态：

```cpp
enum class HitResult { Block, PassThrough, Miss };
```

| 三态 | 语义 |
| --- | --- |
| `Block` | 事件到此为止 |
| `PassThrough` | 有东西但让过 |
| `Miss` | 这里没东西 |

- **遮挡 ≠ 未命中**：半透明遮罩是 `Block`，不是 `Miss`。
- 投递还需要目标：query 在给三态的同时要带上是哪个组件，否则事件没地方投。
  落地时可以是「三态 + 目标」的返回结构，不必硬塞进一个 enum。
- **冒泡和穿透是两种语义**：命中目标先处理，返回 true 就不再往上冒泡，返回 false
  交给父组件；穿透（`PassThrough`）是「有东西但让过」，继续往下找。半透明遮罩挡点击
  靠的是 `Block`。

## 7. 动态组件

- 动态组件自己维护命中状态，或自己判断。
- 点击时不需要遍历它们，状态是现成的。
- 状态必须和渲染同 `t`，否则快速动画差帧。
- 动态组件「自己监听」= 它本来就在运行，自己判断命中。
- 拖动类交互（滚动条、分割条、拖窗口、框选）不再做「路由层 pointer capture」：
  拖动中的组件本来就是动态组件，自己判断、自己维护状态，鼠标移动又持续标脏，
  所以按住期间每一帧都会重查，等价于捕获。移出矩形还算不算自己的，由组件自己定。

## 8. 反向注册与生命周期

场景是场景，父组件是父组件。所有组件都要注册到一个场景里，设置父组件本质上
不过是设置锚点或者 layout 罢了。

- 组件影响命中的变化 → 调 `markDirty()`。
- **生命周期成对处理**：移除、移动、销毁时更新指针，否则野指针。
- 标脏指向**最近的表边界**，避免脏标记一路标到根、白重烘。

## 9. 三档 UI 与各自的命中方式

| 档位 | 判据 | 命中方式 | 代价 |
| --- | --- | --- | --- |
| 静态（场景、面板、菜单栏、按钮组） | 两次配置变更之间几何不变 | 烘焙成索引表，脏了才重烘 | 查表 O(1)，每帧 0 |
| 整块在动（抽屉、Toast、下拉、弹窗） | 动的是一棵子树，子树内部相对位置不变 | 子树自带子表 + 变换通道 | 全程 0 次重烘，查表时把点反变换 |
| 每帧自变形（粒子、进度指示器、动态碰撞体） | 形状每帧都在变 | 不进表，自己响应 | 只有它自己付代价 |

场景本体永远属于第一档（第 2 节），后两档都是 widget 层的动态组件。

## 10. 表的结构

### 10.1 key 必须离散

`unordered_map<矩形, 控件>` 做不到：矩形当 key 只能精确匹配，答不了「包含」。
能当 key 的只有离散位置——格子索引，或者规则网格的行列号。

### 10.2 基本形态

网格索引 + CSR 候选数组（原型的 `src/ink/ui/HitTable.cpp` 已是这个形态）：

- 包围盒按格子边长切方格，每条条目登记进它覆盖到的所有格子；
- 查表 = 一次除法定位格子 + 扫该格候选；
- 候选按 zindex 降序填，「第一个真正包含该点」的就是最上面那个；
- 格子只负责缩小范围，是否命中仍由矩形自己判定，所以不会邻格误命中；
- 零分配、零指针追逐、零哈希（换成哈希 key 语义等价，数组更省更连续）。

### 10.3 不要均匀切格，按 UI 分布聚类

均匀网格有两条代价：建表要遍历整个画布（与 UI 有多少个无关）；粒度被迫折中
（粗了密集区候选多、早退失效，细了空白区格子数按面积涨）。

聚类方案：

- 粗块（只有含 UI 的块才存在）+ 块内细分，每个簇用自己的 cellSize；
- 查询 = 定位簇（簇数量少，线性或二分）→ 簇内查表；
- 额外收益：只碰一两个簇，热数据集中，缓存友好；
- 建表时间正比于 UI 数量，不再正比于画布面积。

### 10.4 形状决定索引

生成器按配置里的布局类型挑专用结构，而不是让人去调一个通用 cellSize：

| 布局 | 结构 | 复杂度 |
| --- | --- | --- |
| 等宽等距（菜单栏、工具栏、分页条） | 纯算术 `index = (x - rowX) / (w + gap)` | O(1)，无表 |
| 不等宽但数量固定 | 排序区间数组 + 二分（k 小就直接线性） | O(log k) |
| 规则网格（tile、矩阵、表格） | 行列取整 | O(1)，无表 |
| 散乱 | 簇内小表 | 见 10.3 |

通用结构只是兜底。编译期知道一切的最大收益不是「空间索引调参更准」，
而是对每种布局生成专用查找。

### 10.5 四条必须写死的规则

1. **兜底条目单独存**：空白区不进表，点在空白的答案来自一条「全局兜底条目」
   （根场景 / 背景板），簇查完没命中再问它，不要复制进每个簇。
2. **溢出桶**：运行时新增的 UI 不在生成的结构里，必须有线性列表兜住，
   命中时与簇结果比 zindex。没有这条，动态 add 的场景就是 bug。
3. **动态组件的「洞」**：静态表里把动态组件占的区域登记成洞；点不落在任何洞里，
   就不用再问动态层，静态表的最上面一个直接说了算。
4. **跨簇条目**（下拉菜单压在菜单栏和面板上）：登记多份还是抬到粗层，
   规则必须先定，否则遮挡与层级会错。

## 11. 动画：配置 + 编译期采样

- 动画写在配置（CXXCSS）里，生成器把曲线烘成「每帧一个值」的采样表；
  播放就是一次数组索引——没有贝塞尔求值、没有 easing 分支、内存连续。
- **变换通道优先**：平移 / 缩放 / 旋转不改表，查表时把点反变换进容器本地空间
  （平移缩放的逆是解析的；旋转后父层那条 AABB 也按帧采样好）。
  表全程冻结，每帧只写一个「当前采样索引」。
- 配置语法上把 **transform 通道**（translate / scale / rotate / opacity）与
  **layout 通道**（width / height / 会导致兄弟重排的定位）分开：
  前者不碰表，后者必须重烘受影响的子树，且受影响范围由生成器算好。
- 两端稳定态（抽屉关 / 开）= 两张烘好的表 + 中间变换插值，全程 0 次重烘。
- **命中与渲染必须用同一个 t 的快照**，否则快速动画下会差一帧（画在这儿、点在那儿）。
- **动画期间 hover 必须每帧重算**：鼠标不动、抽屉滑过来，指针底下的控件已经变了，
  但没有任何鼠标事件会触发。这条由第 5 节的 isDirty 生命周期保证：动的那一帧标脏，
  跟着查一次；不动的那几帧不查，hover 状态保持不变。
- 长驻循环动效（呼吸、跑马灯）用短表循环或保留解析式，别烘长时间轴。
- 采样表体积 = 时长 × 采样率 × 通道数（1 秒 120Hz 单通道 120 个 float，可忽略）。

## 12. 无限 / 虚拟化内容（Excel 型）

前提是「无限」永远不进表：

- 表里只装 viewport + 缓冲的可见格（例如 40×25 = 1000 格）；
  总行数是数据层的概念，内存上限 = 可见格数 × 每格条目，与总行数无关。
- 滚动 = 变换：点反变换到内容坐标，取整得 (col, row)，O(1) 查或算。
- 规则网格不需要空间索引（坐标 → 索引是算术），所以「内容自管理」不仅可行，
  而且比通用表更快。
- 拖选单元格这类**范围查询**只有规则网格能做，哈希表做不到。
- 单元格实例池化复用，只有可见的几十个存在。
- 空白格点击由网格自己兜（= 选中那个单元格），不需要表兜底。

## 13. 复杂度小结

- 常见：一次 query 命中最高层即停，1~2 层，每层 O(1) → 整体 O(1)。
- 最坏：点在空白或一路穿透到底 → O(总条目数)，不是层数的平方。
- 建表：聚类后正比于 UI 数量，不再正比于画布面积。
- 每帧：`isDirty == false` 时 0 次 query；`isDirty == true` 时 1 次 query，
  外加帧计数尾巴那几帧。点击额外 1 次。

**本文没写、`test002` 另加了的一路：重绘方案。** 输入是「脏了重新 query」，
重绘是「脏了重新画一帧」，两者形状相同但**独立实现**（各自一份脏标记 + 帧计数）：
`include/core/RedrawScheduler.h`。约定只有一句——**需要重绘的属性，写入口自己
明确调 `makeDirty()`**；几何 / 可见性 / 层级由写入口内部顺带标一次。这样
「外观变化标重绘、不标命中」是写出来的，不是分析出来的。

**从原型到本方案要改的，按优先级**：

1. 三态返回：命中结果从「单一目标」变成 `Block / PassThrough / Miss`，并带上目标
   （第 6 节）；
2. `isDirty` 生命周期 + 帧计数，取代「命中一次就缓存」的快照路由（第 5 节）；
3. 写入口 `final` + 内置 `markDirty()`，只留 `onXxxChanged` 钩子（第 3 节）；
4. 显式 zindex 取代 `_order`（构造顺序）（第 1 节）；
5. 场景静态化：`Scene` 去掉位置 / 尺寸写入口，动态需求下沉到 widget；
   原型里的「动态子树 = 动态洞」改成「动态组件 = 洞」（第 2、9、10.5 节）；
6. 表边界：脏标记只标到最近的表边界，不再一路标到根（第 8 节）；
7. 反向注册：组件登记到场景，父子关系退化成锚点 / layout（第 8 节）；
8. 聚类索引 + 按布局类型生成专用查找（10.3 / 10.4）；
9. 溢出桶，接住运行期新增的组件（10.5）；
10. 拖动类交互不再做路由层的 pointer capture，交给动态组件自管（第 7 节，待确认）。

   - letterbox / DPI 换算与设计坐标归一（原型 `toDesign()` 做的是这件事）。

## 16. 一句话版本

> **场景静态，widget 动态。写入口 final 内部标脏，只允许重写钩子。鼠标移动、几何、
> 层级、可见性变化 → isDirty；颜色文字不标。每帧 isDirty 就 query，帧计数清脏；
> 点击单独 query。静态查表，动态自判，按 zindex 合并三态，阻塞停、穿透继续、
> Miss 兜底。组件反向注册到最近表边界。**

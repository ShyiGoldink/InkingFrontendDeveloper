### T-1：形状层第二档（`capsule` / `ring` / `line` / `polygon`）

把形状词汇补全。现在生成器对这几个名字报"**格式里有定义，但形状层还没实现**"
（区别于"不认识"），说明**配置格式早就留了位置**，只差实现。

**上下文 / 落点**

- 第一档（`rect` / `roundedRect` / `circle` / `ellipse`）已就位，形态是
  **一份定义派生三个量**：`SignedDistance`（渲染）/ `ShapeContains`（命中）/
  `GetShapeBounds`（AABB），全在 `include/ink/dataStruct/InkingShapeSpec.h`。
  加形状就是**加 SDF 分支**，三个量自动跟上——这是当初定这个结构的用意。
- **填充**也要跟着认：`src/ink/basic/InkingDraw.cpp` 的轮廓采样现在是
  "按形状类型分别采样"，`roundedRect` 的圆角走 `AppendArc`，新形状多半能复用。
- **生成器**：`tools/inkgen/Cxxcss.cpp` 的 `ReadShape` 里有一张"尚未实现"名单，
  实现一个就把它挪到上面去（并接受它的新参数字段）。

**新字段（想清楚再定名字，写进 `CXXCSS.md` §3.3 的表）**

| 形状 | 需要的参数 |
| --- | --- |
| `line` | `thickness`（线宽）、`cap`（端点：butt / round / square） |
| `ring` | `thickness`（环宽） |
| `polygon` | `sides`（边数）、`rotation`（起始角） |
| `capsule` | 不需要（两条半圆 + 一个矩形，用满 w×h） |

**坑（都是前一轮踩过的同类）**

- `rotation` 的单位要跟 `transform.rotate` **统一成度**（`InkingTransform.h` 定过这条）；
- `line` / `ring` 的 AABB 要含 `thickness`，否则命中表登记不全 → 漏命中；
- 轮廓采样：`polygon` 的顶点顺序与绕向要一致（扇形三角化靠它）；
- 采样步数用现成的 `StepsForLength` 估，别写死。

**怎么算完成**：`ink_button_test` 里对每种新形状各一条"**填充与命中同源**"的断言
（角 / 边不命中 + 离屏像素对账），生成器自检里去掉对应的"尚未实现"用例。
观感（线的粗细、环的均匀度）按 r5 交给你看。

### T-2：缓动曲线（`easing`）

现在的过渡一律 **linear**（`TaskGuide` 的 D-1 当时特意留的坑位：
"缓动先留 linear，要不要 easing 曲线，实现时再定"）。

**上下文 / 落点**

- 插值全部收在一处：`include/button/ButtonLook.h` 的 `Advance` 里
  `const float k = finished ? 1.0f : (elapsed / duration);`——
  **只要把 k 过一遍缓动函数**，颜色与变换会一起跟上（它俩共用一个 k）。
- 配置写在状态自己身上，和 `duration` 并排：
  `"transition": { "duration": 0.15, "easing": "easeOut" }`。
- 生成期校验 + 烘进 `ButtonAppearance`（照 `transitionSeconds` 那条路走一遍）。

**先给一组具名曲线就够**（自定义 `cubic-bezier` 留到以后，它要解析 4 个控制点、
还要想清楚怎么写进文档）：

`linear`（默认）/ `easeIn` / `easeOut` / `easeInOut`

**坑**

- 缓动**只改变进度**，不改变时长、起点、终点；`duration` 与 `easing` 互相独立。
- 收尾那一帧要**直接落到目标值**（现有实现就是这么做的），别让缓动函数在
  `k = 1` 处留浮点误差。
- 中断（中途切状态）时起点取当前显示值，缓动要**从头算**（现有语义），
  别试图"补偿已经走过的曲线"。

**怎么算完成**：数值可测——断言 `easeOut` 在**前半段**走得比 `linear` 快、
`easeIn` 比它慢，且三者在 `k = 0 / 1` 处一致。手感顺不顺按 r5 交给你。

### T-3：文字渲染（字形图集 / 纹理层）

把按钮上的文字从**占位方块**变成**真文字**。

**上下文 / 落点**

- 替换点是**单一**的：`src/button/ButtonPaint.cpp` 的 `detail::PaintButtonText`——
  现在是"按 fontSize / leftSpace / topSpace 画一块同尺寸方块"，当初就是为了
  让这个替换只动一个函数体。
- `SDL3_ttf` 已经接进来了（`cmake/SDL3_ttf.cmake`，可选依赖），自检
  `tests/test_ttf.cpp` 已经验证过"开字体 / 量中英文尺寸 / 查汉字字形"。
- **顺带解掉一条已知限制**：占位方块不跟 `transform` 走（按钮转了字还在原地），
  因为它用 `SDL_RenderFillRect` 画、只能画轴对齐矩形。改成**纹理**之后，
  文字自然能跟着变换（纹理绘制支持旋转）。
- 多语言走运行期：`SetText(s)` 那条路已经有了（`UsageReport` §6 有）。

**要做的事**

1. 一个**纹理层**（新建 `include/ink/basic/InkingText.h` 之类）：给
   （文本 + 字号 + 颜色）出一张纹理，缓存起来；
2. `PaintButtonText` 改成从纹理层取纹理来画；
3. 文本变了（`SetText`）要**让缓存失效**——这是最容易漏的一处。

**坑**

- 纹理的**生命周期**：谁拥有、什么时候销毁（渲染器销毁前必须放掉）；
- 缓存键要包含**颜色**（同一句话换色要重画）；
- 先做"一个字符串一张纹理"就够，字形图集（逐字形排版）是更后面的优化；
- 中文字形多，别在启动时预烘整张字库。

**怎么算完成**：离屏渲染 + 像素（文字区域出现非底色像素、`SetText` 之后重画变了）。
**好不好看（字号、间距、字体）按 r5 交给你**——这类没有数值判据。

### T-4：`img` / `svg` 两种外观

现在生成器把这两种 `type` **收下并提醒"还没落地"**，运行期不画。

**上下文 / 落点**：依赖 **T-3 的纹理层**（两种外观最后都落到"画一张纹理"）。

- **`img`**：`CXXCSS.md` 定的路子是"图像**绝对路径**，编译期转成二进制纹理"
  ——生成器把文件读成字节数组烘进生成代码，运行期用 `SDL3_image`（已接入）解码
  一次、进纹理缓存。参考配置 `tests/fixtures/cxxcss/Button/imageButton.json`。
- **`svg`**：全量 SVG 是 XML 解析 + path 语法 + 曲线细分，**不是顺手能做**的。
  合理范围是先定**支持子集**（`rect` / `circle` / `ellipse` / 只含直线与圆弧的
  `path`），**生成期**转成形状层能表达的东西（正好复用 T-1 之后的形状词汇），
  不支持的标签**明确报错**。

**坑**

- 二进制烘进生成代码会让产物变大——先定个上限（几 MB？）并**超出就报错**，
  别让某天有人放进一张 4K 图把编译撑爆；
- `img` 的解码时机（进程启动 vs 首次渲染）要想清楚；
- SVG 子集的边界要**写进 `CXXCSS.md`**，否则用户不知道哪条路能走。

**怎么算完成**：一张小 PNG → 离屏像素验证画出来了；SVG 子集每条一个用例 +
"不支持的标签报错"的用例。观感按 r5 交给你。

### T-5：布局通道动画（"每态一份几何 / 表" + 换表时机）

**这一条是 `D-1` 修订里明确留下的对偶**：

| 通道 | 例子 | 命中表 |
| --- | --- | --- |
| **变换**（已做，T-2 上一轮） | `translateX/Y` / `rotate` / `scale` | **不用动**：表按本地形状烘，查询时反变换 |
| **布局**（就是这条） | `width` / `height` / 会让兄弟重排的定位 | **必须重烘**受影响子树——"每态一份表"该出场了 |

你早先的判断正是这条的地基：**"写进配置就是可预测的，所以表的内容可以提前
烘焙好；而几何动画有明确的响应事件（三态切换），换表也就有明确的时机。"**

**上下文 / 落点**

- 命中表（T-4 上一轮）已经是"簇 + 格子 + CSR + 动态洞"，重建成本正比于组件数；
- 标脏三种（T-3 上一轮）已就位：命中脏（帧首重烘）就是这条要用的消费点；
- 三态是**有限的**（normal / hover / onclicked），所以"每态一份几何"是个
  有限集合——这正是它可预测的原因。

**★ 开工前必须先确认的一件事：静态档的定义**

现在的"静态"是靠**类型**保证的：`InkingStaticAnchor` 没有几何写入口，
`src/ink.cpp` 用编译期断言钉死。而"三态各自有不同尺寸"意味着几何会变——
所以这条要么：

- **(a)** 把静态档的定义精确成"**几何取自一个构造期烘好的有限集合**"，
  给它一个**受控的枚举切换入口**（不是任意写入口），断言跟着改；或者
- **(b)** 让"会改尺寸的按钮"落到动态档，静态档仍然只管颜色 / 变换。

**这是个需要你拍板的决定**（按 r6 暂停问），不要自己选一个就埋头做。

**坑**

- 场景绘制列表里存着**静态节点的坐标快照**（`DrawItem::absX/absY`）——
  尺寸一变，快照与命中数据都要重算；
- 兄弟重排：如果一个组件的尺寸变化**影响兄弟**，那受影响范围要由生成器算好
  （`InputDesign.md` §11 的原话），这比"自己变"复杂一个量级。**先做"不影响兄弟"
  的那半**（自己的尺寸变、锚点不变），重排留到确认之后。

**怎么算完成**：断言"切到 hover 后实际尺寸变了、命中区域跟着变、表数据跟着更新、
兄弟位置不变"。

### T-6：静态烘焙（顶点缓存 + DrawCall 合批）

项目一句话里写着"渲染 = DrawCall 合批 + 静态烘焙"，而这一块**至今没落地**：
现在是一节点一次 `SDL_RenderGeometry`。你自己也说过"**最头疼，放最后优化**"。

**上下文 / 落点**

- **信号已经备好了**：T-3 的**重绘脏**（+ 连续 5 帧自清）就是"这个节点的顶点
  还能不能复用"的判据；当时的注释里就写着"将来：重算顶点 / 重提 DrawCall"。
- 现在的填充入口：`src/ink/basic/InkingDraw.cpp` 的 `detail::fillShape`——
  它自己"生成顶点 + 立刻提交"。要拆成**生成到缓冲**与**统一提交**两步。
- 场景渲染循环（`InkingScene::Render`）现在是逐节点 `SubmitToRenderer`。

**要做的事（建议分两步，各自可交付）**

1. **顶点缓存**：静止节点不重建顶点（用重绘脏判断），只重用上次的顶点；
2. **合批**：把同批节点的顶点合成**一次** `SDL_RenderGeometry` 提交。

**坑**

- 合批会打乱"逐节点提交"这个隐含假设：**z 序**（批次之间的先后）、
  **混合模式**、（以后还有）**纹理 vs 纯色**都要分组处理，别把顺序搞错——
  "画的是一个、点的是另一个"这类 bug 就是这么来的；
- `SDL_RenderGeometry` 单次调用的顶点数上限要查清楚；
- **性能类改动要留一个能断言的计数**（`AGENTS.md` §6 第 40 条那条教训：
  把两种脏合并时功能全对、只是白干活，只有计数抓得住）。
  这里就是"顶点重建次数"。

**怎么算完成**：**像素回归**（`ink_render_probe` / `ink_button_test` 的离屏采样
必须一模一样）+ "静止节点的顶点重建次数不增"的计数断言。

### T-7：组件树子表（`InputDesign.md` 的「整块在动」那一档）

三档 UI 里的第二档：**动的是一棵子树，子树内部相对位置不变**
（抽屉、Toast、下拉、弹窗）。做法是**子树自带子表 + 变换通道**，
于是"全程 0 次重烘"，查表时把点反变换进子树本地空间。

**上下文 / 落点**

- 现在只有 **Button 一个组件类型**，而且**没有子表**——锚点有父链（`GetParent`），
  但没有"父 → 子列表"。`AGENTS.md` 的未实现清单里明确写着这一条。
- 变换通道（`InkingTransform.h`）与命中表（`HitTable`）都已经就位，
  但**变换只作用于组件自己**（`UsageReport` §7.4 记着这条限制：
  "变换只作用于组件自己，不影响子级"）——这条要在这里补上。
- 顺带会牵出两件**一直被挂着的事**：
  - **局部层级 / 堆叠上下文**：有了它，`InputDesign.md` §10.5 规则 4 的
    "跨簇条目仲裁"和规则 2 的"溢出桶"才**有意义**（这两条当初被评估为
    "当前不需要"，理由正是"z 序全局唯一"）；
  - **多场景叠加**（弹窗 / Toast）——`§15 开放问题 3`，会决定
    "同期只有一个场景可渲染"要不要放宽。

**要做的事（建议先做最小闭环）**

1. 锚点加**子表**（构造 / `SetParent` / 析构时维护）；
2. 容器的**变换通道**：父一变，整个子树的绘制与命中跟着动
   （命中用反变换，不需要重烘子表）；
3. 一个**演示组件**（例如 `Panel` / 抽屉），并且它得是真组件——
   于是这一步顺带产出"第二类组件"的样板；
4. 局部层级（可选，看第 3 步之后顺不顺）。

**坑**

- T-3 的**坐标快照**（静态子孙用列表里的绝对坐标）会在这里失效——
  子树整体平移时快照过期，这正是"子树自带子表"要解决的；
- 命中表的登记是"绝对包络"，子树动起来之后子节点的包络也要跟着动
  （或者干脆按"子树自判 + 外层查表"分两层，参考 `InputDesign.md` §9）；
- 别急着做通用布局系统——这一步只解决"**整块在动**"。

**怎么算完成**：断言"容器平移 / 旋转后，子节点的命中位置跟着走、而且没有重烘
（表条目数不变）"；观感按 r5 交给你。

## 交接现状（开工前先看这一节）

目标是**省掉"读四份大文档才够开工"的开销**。这里只放开工必需的，
细节指向对应文档（每一行都指了地方）。

### 现在能做什么（一句话一条）

- **配置 → 生成 → 窗口**这条链路是通的：`CXXCSS/Button/*.json` →（构建期 `inkgen`）
  → 每个名字一个按钮类 → 手写场景里一行构造；
- **两类按钮**：静态（几何构造即定型、进命中表、场景**推**输入）与
  动态（几何可改、不进表、自己**拉**输入、收逻辑步 `Tick`）；
- **三态 + 过渡**：颜色与**变换**（平移 / 旋转 / 缩放）按同一段时长插值，
  目前一律 linear（本轮 T-2 补缓动）；
- **形状层第一档**：`rect` / `roundedRect` / `circle` / `ellipse`，
  渲染与命中**同一份定义**，边缘抗锯齿（本轮 T-1 补第二档）；
- **输入**：烘焙命中表（簇 + 格子 + CSR + 动态洞）+ 三态
  （`Block` / `PassThrough` / `Miss`）+ 全局 z 序合并；
- **标脏**：命中 / 重绘 / 指针三种，各有消费点，帧末统一消费、静置自清；
- **场景**：手写（5 行），构造即登记；同名同期只能有一个；
- **还没做**：真文字、`img`/`svg`、第二档形状、缓动、布局通道动画、
  顶点缓存 / 合批、组件树子表 —— 就是本轮这 7 个任务。

### 开工前必须知道的三条

1. **一个 Button 一个名**（D-2）。`name` 直接就是类名，同名在两个 json 里出现会在
   **构建期**报错。
2. **`build/ring.py` 没有进 git**（`.gitignore` 第一行就是 `build/`）。它是 r2 / r4
   的提醒工具，删掉 `build/` 或换机器就没了——需要时得先重建。
   实测 `python` / `py` 都能跑，`tkinter` + `winsound` 可导入。
3. **验证方式**：能变成数值判据的自己写断言（渲染类用**离屏读回**，参考
   `tests/render_probe.cpp` / `tests/test_button.cpp`）；需要"看图"的按 r5 停下来
   交给你。开窗截图在这台机器上会被别的窗口挡住，别试。离屏采样要同时满足：
   **逻辑分辨率 + 混合模式开启 + 场景是活跃的**，少一个的表现都是"采到的永远是
   一片底色"（`AGENTS.md` §6 第 32、33 条）。

### 几处别踩的地方（都是真踩过的）

- 公开头里**不要** include `<SDL3/SDL.h>`（只前向声明；`SDL_Event` 是 `union`）；
- 生成物、日志、临时文件**只落 `build/`**，源码树保持干净；
- **别用 PowerShell 读写源码文件**（`Set-Content` 会把中文注释写成乱码）——
  这条连"只改一个名字"都算，见 `AGENTS.md` §6 第 21 条；
- 手写 `ButtonData` 要显式置 `hoverInheritsNormal = false`，否则 `Normalize()`
  会拿 normal 把 hover / onclicked **整个吞掉**（症状："状态切了但外观没变"），
  见 `AGENTS.md` §6 第 43 条；
- 其余坑按主题查 `AGENTS.md` §6（42+ 条，每条都是实测踩出来的）。

## 已确定的决定（仍然有效，实现时按这个来）

### D-1 Animation 用 **transition 风格**，且**跟三态绑定**

- **写法**：状态里加 `transition`，例如
  ```jsonc
  "hover": { "type": "color", "source": "1|1|1|0.85", "transition": { "duration": 0.15 } }
  ```
- **触发**：进 hover / 按下 / 抬起时**自动跑**，不需要单独写事件绑定。
- **不碰本地几何** —— 这样按钮仍然是**静态组件**，能继续待在"进命中表"那一档。
  颜色不标脏；**变换**（见下面那条修订）不改表，所以也不破坏这个前提。
  真会改表的只有**布局通道**（尺寸 / 会让兄弟重排的定位）——那是本轮的 **T-5**。
- **过场段**（normal→hover、hover→pressed、pressed→hover…）各自带时长，缺省用 `duration`。
- **不做打断过渡**：三态直接切、动画只负责把值插过去。简单优先。
- 缓动先留 `linear` —— 本轮的 **T-2** 来补。

> **2026-10-02 修订（用户要求）：允许"移动 / 旋转"这类**变换**，措辞从
> 「绝不碰几何」精确成「不碰**本地**几何」。**
>
> 原因：`T-3`（重绘 / 标脏）与 `T-4`（输入机制）都要有"几何在动"的真实对象可依赖，
> 而用户指出配置里的动画是**可预测**的——写进 json 就意味着形态是有限集合，
> 不需要每帧重算。
>
> 落地方式选了比"每态一份烘好的表"更省的一种，`InputDesign.md` §11 早有原话：
> **变换通道不改表，查询时把点反变换回本地空间**。所以：

| 通道 | 例子 | 命中表 |
| --- | --- | --- |
| **变换**（已做） | `translateX/Y`、`rotate`、`scale` | **不用动**——表按本地形状烘，查询时反变换 |
| **布局**（本轮 T-5） | `width` / `height` / 会让兄弟重排的定位 | 必须重烘受影响子树——那时"每态一份表"才是正解 |

> 于是**静态档也能移动 / 旋转**，而且**仍然进命中表**：绘制过正变换、
> 命中过逆变换，两者严格互逆（自检里"扫一片区域逐个点对账像素与命中"，
> 旋转 90° / 45° 各查了一万八到三万多个点，不一致 0 个）。
>
> 两条约定（运行期同一份定义在 `include/ink/dataStruct/InkingTransform.h`）：
> **原点取组件中心**（等价 CSS `transform-origin: 50% 50%`）；
> **`rotate` 单位是度**、顺时针为正。

### D-2 动态 Button 命名：**交给 json 的 `name`**，且**必须一个 Button 一个名**

- 生成器**不加** `Static` / `Dynamic` 前缀 —— `name` 就是类名（`normalButton` → `NormalButton`）。
- 动态的那份自己起名（例如 `DynamicTestButton`），建它自己的 json。
- **必须一个 Button 一个名**：生成器靠名字找类、做二次确定；
  同名会在生成期被拦下（运行期的库也会驳回后来者，但那是静默的错，晚一步难查）。
- 副作用先说清：因此**静态版与动态版是两份 json**，共同的颜色/尺寸会重复。
  要消掉重复得另加机制（例如 json 之间的 `extends` / 共享块）——**未决定**，
  需要时再提。

### D-3 命名修正

任务里写的 `InkingDynamicAnother` 在仓库里是 **`InkingDynamicAnchor`**
（`include/ink/basic/InkingAnchor.h` 末尾）。

### D-4 场景**不生成**，手写（2026-10-02 评估）

`CXXCSS/Scene/*.json` 曾经实现过一版并跑通，评估后撤销：生成场景的两处收益
（组件不传 `parent`、名字有编译期保险）手写都能拿到——前者靠"成员 + 默认成员
初始化器 `{this}`"，后者靠生成的**按钮类**（类型名拼错即编译错误）与一行常量；
而代价是固定的（一个界面看两组文件、不能按条件建组件等）。
完整理由在 `CXXCSS/CXXCSS.md` §7.2。推荐写法与示例见 `examples/scene_demo/`。
